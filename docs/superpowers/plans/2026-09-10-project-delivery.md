# MockCharles 五阶段推进计划

日期：2026-09-10。状态：项目级执行规划，未开始应用开发。阶段顺序来自用户本轮要求；具体未决行为仍以决策登记为准。

**目标：** 按功能分析 → 模块详细设计 → UI 设计 → 界面实现 → 测试用例编写，交付四模块一致、可操作、可验证的桌面界面。

**架构：** 沿用 Wails v2 + Go + Vue 3/TypeScript + SQLite。设备管理、规则管理、规则集管理、流量是产品模块；代理、证书、生成器、存储与 MCP 是支撑能力。前端持有草稿和筛选，已保存配置与真实运行状态由核心提供。

**执行方式：** 这是阶段计划，不是已冻结接口下的编码任务单。后续按本文件逐阶段推进，应用编码任务在相应详细设计与 UI 评审完成后单独拆分，可使用 executing-plans 技能在当前任务执行；本计划不要求并行代理。

## 2. 全局约束与阶段完成标准

- 一级业务模块固定四个；项目与设置是公共入口，样本/业务数据归规则编辑辅助。
- 全部 IP/单 IP 与流式/目录式是两个独立维度，四种组合均纳入 UI 和测试范围。
- 保留已有固定/随机响应、双向 Header、优先规则集及顺序执行；D17 未明确延期前不取消顺序能力。
- 多项目同时服务，每 IP 同时绑定一个项目；切换查看项目不改变绑定。
- 新 IP 真实转发；未绑定来源 Header 的作用域在 D20 收口。
- 启动不自动监听；关闭窗口退出并停止代理；旧顺序运行不自动恢复。
- AI CRUD 保留已确认范围，首版禁止 AI 绑定设备、切模式和控制运行。
- 首版目标为 Windows x64、macOS Intel 与 Apple Silicon；不承诺尚未实测的最低系统或性能数值。
- 顺序按用户指定五阶段执行。第五阶段集中编写正式用例；前四阶段记录预期结果，界面实现期间执行构建、类型检查及必要功能验证，不将所有质量检查拖到最后。
- 对当前模块有实质影响的未决行为在进入其 UI 定稿前解决；无关未决项不阻塞其他模块设计。
- 本计划的终点是形成测试用例及明确可执行范围；用例编写完成、用例执行通过、产品发布是三种不同状态。

| 规则 | 匹配表达式、Header 多值操作、响应版本、随机配置、材料引用；校验/预览/保存/删除与冲突 | 04、05、06、09 |

- [ ] 为字段定义类型、必填/可空、默认值、枚举、校验、可编辑入口和持久化归属。

## 6. 阶段四：界面实现

**输入：** 已评审 UI、模块契约及确定的功能范围。具体编码步骤在此时按模块细化，不在接口未冻结时预造实现代码。

建议目录：`frontend/src/features/devices/`、`rules/`、`ruleSets/`、`traffic/` 管理各模块页面；`frontend/src/components/` 放复用编辑器与状态组件；`frontend/src/services/` 放契约及桌面适配；演示数据与真实适配分开。最终文件名在模块编码任务中落实。

| 增量 | 实现内容 | 可独立检查的产出 |
| --- | --- | --- |
| I0 公共壳 | Vue/TypeScript 工程、导航、项目上下文、布局、基础组件和数据适配边界 | 可启动、四模块可切换、构建和类型检查通过 |
| I1 设备 | IP 列表、备注、证书与绑定、运行状态、流量跳转 | 已设计的输入/失败状态可重现，跳转正确带入 IP |
| I2 规则 | 匹配/Header/响应编辑、材料选择、预览/保存/冲突 | 草稿与已保存状态区分，校验和引用反馈符合规格 |
| I3 规则集 | 成员引用、排序、两种编排、设备运行详情 | 顺序含义清晰，失败不保留虚假的已保存顺序 |
| I4 流量 | 四种组合、统一详情、筛选、目录计数与分页、长列表 | 同范围请求不丢失，选中记录可跨视图定位 |
| I5 跨模块 | 从流量创建规则、加入集合、绑定、回看结果；真实适配接入 | 完整流程及连接故障行为与规格一致 |

- [ ] 每个增量先核对 UI/接口映射，再实现页面与状态，最后运行该增量需要的构建、类型和交互检查。
- [ ] 演示适配使用独立入口或明确演示标识；不能用前端模拟结果显示“真实代理已启动”“设备已信任”或“实际命中成功”。
- [ ] 真实绑定/证书/规则执行依赖 Go 核心：相应能力未实现时登记依赖，实际操作不可假成功；若要交付可用桌面功能，需按 10 专题落实核心实现与联调。
- [ ] I5 明确记录每条路径是“演示交互完成”还是“真实连接已验证”。后者必须有真实请求或持久化结果佐证。
- [ ] 对不同窗口大小、长 URL/JSON、大列表、事件重连和草稿保留逐项核对 UI 规格。

**交付物：** 可运行界面、与真实核心隔离的演示适配、实现状态表、构建及交互检查记录。

**完成条件：** 评审过的界面与交互已实现，无未标识的假成功；约定需要真实接入的路径有联调证据。只有演示界面时明确交付为界面原型，不能宣称完整产品可用。

## 8. 跟踪、变更与下一步

每阶段结束更新 `docs/design-status.md`：产物版本、完成项、未完成项、影响决策与下一步。需求变化回写功能条目，并追踪模块规格、UI、实现和测试，避免只改页面。

不按未知的人力、设备和联调条件承诺工期。估算在阶段二细化任务后形成；不能把测试设备或后端依赖隐藏在“界面完成”内。
