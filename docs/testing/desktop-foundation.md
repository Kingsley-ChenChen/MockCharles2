# 第一阶段：HTTP 固定 Mock 开发验收

状态：已通过自动化核心测试、界面回归和真实 Wails 桥接端到端验证；等待用户 Windows 桌面/局域网实机体验。此阶段不是完整软件交付。

- `frontend/ui-smoke.cjs`：设备间独立、候选选择不启用、浏览项目不改绑定、规则集无运行按钮、目录/单 IP/详情、1100px 布局、草稿冲突恢复、无后端与空工作区区分。
- `frontend/desktop-smoke.cjs`：使用真实 Wails 开发桥接；UI 写入 SQLite 配置；Node 临时上游响应经真实 Go 代理转发；启用设备规则后命中 Mock；停止后恢复转发；流量显示真实记录。
- Go vet、Vue TypeScript 检查、前端生产构建、Windows x64 Wails 编译。
- 独立代码审查发现并修正：IP 来源错误、Header 覆盖、Host、连接收尾、轮询覆盖保存、版本冲突恢复和跨页草稿干扰。

## 请用户验收的内容

1. 打开 `build/bin/MockCharles.exe`：应显示四个模块且代理未开启。创建一个项目。
2. 开启代理。先在本机用下列命令发起 HTTP 请求；设备表应自动出现本机来源 IP。

   ```powershell
   curl.exe --proxy http://127.0.0.1:8888 http://example.com/
   ```

   真实上游结果取决于网络；也可换成你自己的 HTTP 测试服务。不要用 HTTPS URL 做本阶段验收。

3. 在规则管理新建固定规则：方法 GET、URL 与实际请求完全一致（包含末尾 `/` 与查询参数），正文设为 `{"hello":"MockCharles"}`。
4. 新建规则集，把该规则加入并保存。回到设备页，绑定项目、勾选规则集并保存，再打开设备详情点击“启用所选”。
5. 重复请求：应收到配置正文；流量页标记“固定 Mock”。停止设备规则后，再请求应恢复真实上游响应。
6. 在流量页检查所有 IP / 单 IP、流式 / 目录式、详情和清空；流式不出现导出入口，目录式导出明确标为待实现。
7. 关闭并重开：项目、规则、规则集、设备配置保留，代理关闭、流量清空。手动开启代理后，保存的已启用优先规则集可继续匹配。
8. 可选：手机和电脑处于可互通局域网，手机 Wi-Fi 代理填写电脑局域网 IP、8888 端口，发送 HTTP 请求。重点反馈设备发现、文字清晰度、交互顺序和流量详情是否符合预期。
