# HTTPS 与证书开发验收

本阶段实现指定域名解密、其他域名加密隧道、CA 生成/复用、公共证书下载与保存。顺序执行、随机响应、样本和导出仍在后续计划内。

## 已完成验证

- 8 项证书组件测试：首次生成/重启指纹不变、重复生成不替换、DNS/IP SAN、签发验证、无效输入、损坏存储、并发与缓存上限、过期叶证书重新签发、过期 CA 拒绝使用且不自动换根、并发发布不覆盖。
- 17 项核心测试（含上一阶段 10 项）：无 CA 隧道、指定目标解密/Mock/项目 Header、上游证书拒绝、默认 443、IPv6、跨目标请求拒绝、域名列表校验、公共证书下载、CA 异常后关闭解密、停止隧道、半关闭响应与活动隧道可见。
- 浏览器回归：原四模块；CA 生成、配置解密名单、保存不改设备绑定、CA 丢失时仍可关闭解密、保存失败/版本冲突处理。
- 真实 Wails 端到端：UI 生成 CA/保存设置 → 经代理下载 DER → 指纹一致 → Node 严格验证本机 CA 的 TLS 连接 → HTTPS 固定 Mock → 项目响应 Header → 实际流量展示。
- Go vet、前端类型检查/构建、Windows x64 构建。证书组件 Linux 交叉编译通过；这不等同于完整 macOS/手机运行验收。
- 尚未执行 Windows race 检测（环境缺 CGO/C 编译器），尚需 iOS/Android 真实设备信任与 App 网络栈验证。

## 手机测试步骤

1. 打开程序，展开设备页“HTTPS 设置与证书”，点击“生成本机 CA”。生成后自动打开“手机接入与证书安装”弹窗，也可点击同名按钮再次打开。弹窗列出本机当前可用的内网 IP、网卡和代理端口；优先显示实际监听端口，未开启时显示计划端口。再次使用同一数据目录不应生成新根证书。记录 SHA-256 指纹。
2. 开启代理。手机和电脑处于可互通局域网，在手机 Wi-Fi 代理填写电脑局域网 IP 和代理端口，默认 8888。
3. 手机浏览器访问 **`http://mc.invalid`** 下载公共证书。此地址通过本代理提供，不是互联网网站；必须保留 `http://`。也可点击“保存公共证书”导出 `.crt` 再传到测试设备。
4. iOS：安装下载的描述文件后，到“设置 → 通用 → 关于本机 → 证书信任设置”启用此根证书的完全信任。以 [Apple 官方步骤](https://support.apple.com/en-us/102390)为准。
5. Android：系统安装用户 CA 后，自研 App 的调试构建可能仍需明确允许用户 CA。按 [Android Network Security Configuration](https://developer.android.com/privacy-and-security/security-config) 配置调试信任；不要将调试信任配置误用于正式发行包。
6. 桌面 HTTPS 设置中勾选启用，逐行填入测试接口域名（例如 `api.your-app.test`），保存。不要带协议、端口、路径或通配符。重新连接测试 App，使其建立新的 HTTPS 连接。
7. 先不启用设备规则，验证真实 HTTPS 响应能显示完整 URL、Header 和捕获正文。再为该完整 HTTPS URL 新建固定规则并加入规则集，在设备页保存关联并启用；应返回固定正文并显示“固定 Mock”。
8. 访问未列入的 HTTPS 域名：应正常转发，流量显示 CONNECT / “仅隧道转发”，没有解密正文。它不会应用项目 Header 或 Mock。
9. 关闭软件再打开：CA 指纹、域名名单、设备/规则配置保留；代理未启动、流量为空。删除/损坏 CA 的异常场景由自动化测试覆盖，不需要手工破坏日常证书。

请重点反馈设备型号/系统、使用浏览器还是 App、是否成功安装与信任、流量里的错误文字。下载成功不等于信任成功；有证书固定或绕过系统代理的 App 需要自研测试配置配合。

## 当前限制

不提供 CA 自动重建、根证书自动替换、私钥导出或忽略上游 TLS 校验。Windows CA 使用当前用户 DPAPI，因此不可直接把加密存储复制到另一用户/电脑当作可用根证书库。

TLS 1.2/1.3，设备到解密代理仅 HTTP/1.1；没有 HTTP/3/QUIC。未解密隧道保留原协议，30 秒无活动会关闭；解密请求沿用临时 30 秒请求上限。停止代理关闭隧道；已有 CONNECT 连接不会因域名列表编辑而自动改变解密方式。

公共证书接口只返回 DER 证书，没有配置修改接口或私钥数据。原始流量仍不落盘，正文捕获仍为前 64 KiB、最多 500 条会话记录。
