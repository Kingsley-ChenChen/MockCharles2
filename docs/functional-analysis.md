## 2. 编号、优先级与共同规则

下表 ID 是后续设计、UI 和测试的追踪入口。P0 是形成真实接入和固定 Mock 闭环的第一批能力；P1 是仍必须完成的后续首版能力，不等于可省略。条目的“待决”表示具体行为尚缺答复，不能把整条功能判成取消。

共同前置：桌面应用可用；写入对象属于指定项目且引用有效；操作失败不呈现假成功。接口写入校验对象版本，冲突保留用户草稿。实际设备状态与请求结果来自核心，预览和筛选不控制运行。容量阈值、恢复和删除策略在对应决策确认后补到条目。

## 8. 用户流程与验收串联

1. **真实代理闭环：** 启动应用（未监听）→ 手动开启 → 手机按指引接入 → 新 IP 出现 → 查看其流式/目录式和实际详情。HTTPS 信任需真机验证。
2. **固定 Mock 闭环：** 真实响应建规则 → 保存固定响应 → 加入优先集合 → 绑定项目和集合 → 再请求 → 核对实际响应和命中原因。仅保存规则不自动改设备。
3. **Header 闭环：** 配置适用通用 Header → 命中接口追加覆盖 → 比较原始与最终值。D20 已确认未绑定来源不改写 Header。
4. **随机闭环：** 业务记录建模板 → 配置随机字段 → 预览保存 → 多请求检查约束 → 修改源记录 → 已保存模板不变。
5. **顺序闭环：** 两 IP 选同顺序定义 → 分别手动开始 → A/B 步骤各自消费 → 未命中及结束后真实转发 → 重置期间旧请求不能推进新运行。
6. **恢复闭环：** 编辑与另一入口保存冲突 → 保留草稿 → 重新读取/处理冲突；退出后监听消失，重启不自动监听或续跑。

## Charles 行为核对

用户的目录式导出限制是本产品选择。Charles 官方将导出描述为 File 菜单的会话级功能，并支持部分格式导入；会话也能保存和重新打开。参考 [Export](https://www.charlesproxy.com/documentation/using-charles/export/) 与 [Sessions](https://www.charlesproxy.com/documentation/using-charles/sessions/)。不将本项目首版不做导入说成 Charles 没有导入。

D09 本轮确认：退出后不自动保留供重启恢复的流量历史，仅主动导出留存；本次会话可用有界临时缓存。独立保存的规则、设备、规则集、样本不受会话清理影响。

2026-09-11 D05 确认：切模式、改绑或重置时，已选定请求使用旧版本继续完成；新请求使用提交后的配置，旧回调不能推进新运行。应用退出排空时限不包含在本次答复中。

UI 评审补充 D22/D23：DEV-02-03 扩展为设备多关联、单个启用，新增关联保存与启用分离的操作；SET-02-02 的开始/停止/重置用户入口统一属于设备页，运行引擎仍独立。规则集页只读显示多个设备的状态并跳转设备，不有全局启动状态。
