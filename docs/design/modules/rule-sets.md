# 规则集管理模块规格

状态：详细设计草案。关联 [SET-01/02](../../functional-analysis.md)。保留优先匹配和顺序执行两种既有能力，同属规则集管理；不是同一个算法的两种显示方式。D05 已确认在途请求可完成且不能推进新运行。

## 1. 类型与所有权

优先集合只持有规则引用与优先级，没有游标。顺序定义持有步骤快照，运行时只消费当前有效步骤。每个设备只有所选模式对应的路由生效；未命中顺序步骤不回退优先集合。

两种定义属于项目，可供多个设备复用；运行状态只属于单 IP。列表页可统一呈现类型，但暂不将数据库表合并，也不提供类型自动转换。D20 已确认 Header 按项目生效，本模块不存 Header 引用。

## 2. 对象契约

| 对象 | 字段草案 | 不变量 |
| --- | --- | --- |
| PriorityRuleSet | id、projectId、name、note、revision、members | 成员引用项目内规则；整个顺序一次提交 |
| PriorityMember | memberId、ruleId、position | 稳定成员身份，规则正文只有一份；成员级开关是否增加见 D19 |
| SequenceDefinition | id、projectId、name、note、revision、activeRevisionId | 身份与内容版本分离 |
| SequenceRevision | id、definitionId、number、steps | 保存后不可变；开始/重置采用有效步骤快照 |
| SequenceStep | stepId、ruleId、position、enabled、matcherSnapshot | 步骤开关不读取规则的独立启用；同规则可被不同步骤引用 |
| ScenarioRun | runId、sourceIp、bindingRevision、definitionRevisionId、generation、state、cursor | 每设备至多一个活动运行；重置/替换改变代次，不重写旧运行结果 |
| Reservation | reservationId、runId、generation、stepId、requestId | 私有执行对象，UI 不能创建/更新；完成提交必须全字段一致 |

优先集合中重复加入同规则没有新的匹配价值，建议保存时拒绝；顺序步骤允许再次引用同规则表示不同步骤，仍不引入同接口响应轮询新功能。细节通过 UI 校验提示表达，不依赖数组下标推断身份。

## 3. 命令契约草案

| 操作 | 输入 | 结果/校验 |
| --- | --- | --- |
| ruleSets.list/get | projectId、类型/筛选/分页或 setId | 定义摘要/详情，包含引用与关联设备数 |
| ruleSets.save | setId 或新建项目、expectedRevision、名称/完整成员 | 原子新版本；无效/跨项目引用拒绝 |
| ruleSets.reorder | setId、expectedRevision、完整 orderedMemberIds | 新版本；重复/遗漏/越域 ID 拒绝，不保存中间顺序 |
| sequences.save | definitionId 或新建项目、expectedRevision、完整步骤 | 新定义版本；顺序与步骤开关 next_run |
| sets.references | setId、type | 当前绑定设备和需要保留的引用，支持跳转 |
| sets.delete | setId、type、expectedRevision | 删除或引用错误；具体 D10，禁止隐式停止设备运行 |
| runs.get | sourceIp 或 runId | 权威状态、快照、当前步骤与本次结果 |
| runs.start | sourceIp、expectedBindingRevision | 新运行或校验错误；当前模式/选择必须有效 |
| runs.stop | runId、expectedGeneration | 停止旧运行；新请求不再使用该运行 |
| runs.reset | sourceIp、expectedBindingRevision、expectedGeneration | 新代次/最新顺序快照，是否合并开始在 UI 明确，不自动循环 |

绑定由设备管理命令执行；规则集页选择设备只是查看运行，不能因此隐式绑定。开始/停止/重置统一从设备页进入，仅可信桌面入口可执行；规则集页没有运行控制按钮，MCP 不暴露或绕过。

## 4. 请求选择

优先模式对设备保存的集合逐条判断已启用规则，第一条匹配停止搜索，无额外“更具体优先”排序。未命中真实转发。空优先集合等价没有命中。

顺序模式只有 running 时检查当前有效步骤。未开始、已停止、已完成或当前步不匹配均真实转发；禁用步骤只在形成新快照时过滤，不改变当前运行。空有效步骤开始行为 D16 待确认。

命中步骤后读取该规则当前活动响应版本并固定到请求。生成与网络写出在短状态锁之外完成；成功写出后只有 reservation/runId/generation/stepId 仍有效才推进。失败保留当前步骤；后续修复响应后新请求使用新版本。

## 5. D05 的具体竞争语义

时间线：请求 R 在运行 G1 的步骤 S1 选定响应 V1 → 用户重置或改绑，旧 G1 停止/失效并形成新的配置代次 → R 继续用 V1 完成 → 回调发现代次失效，只记录 R 的实际结果，不消费新运行任何步骤。

新请求在变更提交之后读取新配置；已在途请求继续旧计划。后台不能在完成时读取当前绑定给旧流量补写新项目/规则集身份。用户看到旧响应是已接受的行为，流量详情应显示实际旧版本，便于解释。

允许完成不代表取消普通网络超时，也不承诺请求无限悬挂。用户本轮确认针对切模式、重置、改绑；停止代理或退出整个应用的排空时限尚未确认，不能扩大为关闭软件后继续常驻等待。

## 6. 同一步并发（D04 待确认）

建议第一个命中请求预占当前步骤，后续匹配候选在有界队列等待。首请求成功后，候选重新按新当前步判断；首请求失败则可重试原步。确定不匹配当前步骤的请求立即真实转发，不等待。

超时/队列满要返回何种可见行为需确认，不能静默丢请求、自动命中后续步骤或无限等待。重置唤醒旧代次等待者后的计划归属亦须在 D04 具体化；已选定响应的在途遵循 D05，不将候选等待等同于已生成响应。

## 7. 定义编辑与 UI

设备运行区显示本次定义版本与当前步骤，定义编辑区显示最新保存版本。保存顺序/步骤开关提示下次开始或重置生效；响应修改下一请求生效。D06 已确认普通 matcher/Header/独立启用/优先顺序下一请求生效，顺序 matcher 下次开始/重置生效；在途保持完整已选计划。

规则集成员跳转规则编辑，不复制编辑器正文。排序保存失败保留可重试草稿并显示保存版本；不可把乐观拖拽顺序冒充后台已生效。共享定义编辑显示受影响设备，运行进度不共享。

## 8. 验收与剩余边界

两个 IP 使用同一顺序定义，只有各自成功响应推进各自游标。提前/已完成步骤请求不返回其他步骤 Mock。生成/写出失败不推进。并发提交不能重复消费同一预占。

重置前 R 已选 V1，重置后 R 可完成，但新运行游标保持不变；R 日志记录旧定义/绑定/响应版本。切到另一项目后，新请求用新项目 Header，旧请求仍保留已经选用的计划版本。重启配置恢复，顺序不自动开始。

待收口：D04 并发等待/上限结果、D10 引用删除、D16 空组/重置交互、D19 成员开关。技术实现可以先使用独立领域对象，不提前锁定这些未决行为。

UI 评审决定 D22：运行控制属于设备，规则集页只编辑定义和查看关联设备，不直接开始/停止/重置。D23 已确认多关联、单个启用；界面布局通过不等于所有关联语义均已冻结。

D23：关联设备列表由 device_rule_set_links 查询，可含多台设备；区分仅关联、在本设备已启用、在本设备运行中。集合对象没有全局启动状态。每个 IP 同时至多一个 activeAssociationId；此处单运行模型不变。
