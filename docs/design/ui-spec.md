# UI 评审稿 01

日期：2026-09-11。状态：供用户评审的视觉与交互方案，不是已实现的软件。基于四模块详细设计草案与 D05/D06/D07/D09/D13/D20 的已确认部分；未决高级行为继续登记，不用原型替用户作决定。

## 1. 本轮产物与评审范围

可点击设计稿：[review.html](ui/review.html)。无需安装业务依赖，用浏览器打开即可。所有数据与状态均为演示，页面顶部持续标识；无代理、证书生成、文件导出或持久数据修改。

本轮重点评审左侧四模块导航、列表/目录与右侧详情布局、浅色视觉和信息密度、流量范围/视图切换。已有“功能导航 + 工作区”布局方向继续沿用；具体尺寸、视觉与控件组织未标成已确认。

建议采用紧凑视图，适合大量请求和规则的日常排查；页面顶部可切舒适视图比较。舒适视图增加行距，可读性更轻松但同屏记录减少。本轮不另做重复导航方案。

## 2. 视觉与布局建议

| 部分 | 初稿约定 | 原因 |
| --- | --- | --- |
| 公共壳 | 浅灰背景、白色工作区、蓝色强调；左导航约 172px | 将注意力留给请求和编辑内容 |
| 工作区 | 列表/目录自适应宽度，右侧详情约 365px | 列表与详情同时可见，避免频繁开关弹窗 |
| 窗口 | 以 1440×960 评审，兼顾 1100×800；正式最小窗口待评审 | 小窗口保留可用主流程，详情可独立滚动 |
| 字体 | 系统中文字体；URL、IP、JSON 等宽 | 来源 IP 必须完整可辨，不被缩略成相同前缀 |
| 状态 | 文本与颜色并用，区分真实/Mock、进行中/失败 | 不仅靠颜色表达关键执行事实 |
| 密度 | 默认紧凑，可切舒适比较 | 保留桌面调试工具的信息量 |

正式 UI 可以增加分栏拖动、键盘导航和列宽持久化；这些尚未在本轮原型完整实现，不以原型的固定尺寸冻结全部交互。

## 3. 页面与可操作内容

| 页面 | 设计内容 | 本轮可演示 |
| --- | --- | --- |
| 设备管理 | 代理接入区、IP 列表、备注、实际项目/模式/集合、证书指引 | 切换设备；编辑演示备注与模式；查看该 IP 流量；在设备上下文控制运行 |
| 规则管理 | 接口/Header 页签、规则列表、匹配与响应编辑、保存提示 | JSON 格式校验和预览、Header 页签、演示保存；随机编辑仅展示入口 |
| 规则集管理 | 优先匹配/顺序执行分开、引用列表、设备上下文 | 优先级上移、切换类型、只读运行摘要及跳转设备入口 |
| 流量 | 全部/单 IP、独立项目筛选、流式/目录、共享详情 | 四种组合、搜索、选中详情、请求/响应/Header 页签、目录导出范围预览 |

演示边界：配置编辑不写入磁盘，切页可能重新载入样例；演示不会生成真实随机响应，也不会发送请求推进步骤。新建、完整匹配编辑、材料管理、实际证书/导出和设置参数不冒充已完成。这些仍在完整软件实施范围内。

## 4. 已确认行为的 UI 表达

- D05：切配置/重置后旧请求可完成，旧回调不推进新运行；运行详情说明这一点。
- D06：普通匹配/Header/启用/排序下一请求生效；顺序匹配/步骤顺序/开关下次开始或重置；响应下一请求生效。保存提示按操作区分，在途保留版本。
- D07：设备配置恢复，监听和顺序运行必须手动开始；启动原型显示代理未开启。
- D09：流量属于当前会话，不自动恢复旧会话；底栏持续提示导出保留边界。
- D13：流式不提供导出按钮，目录式可预览导出范围；不提供流量导入。
- D20：项目通用 Header、接口专用最后覆盖；未绑定来源不改写 Header；规则集不增加 Header 配置层。

## 5. 建议的评审路径

1. 从流量进入：全部 IP 流式 → 单 IP → 目录式 → 选中重复路径的不同实例，核对来源、计数和详情。
2. 查看目录导出范围预览，再切流式确认没有导出入口。
3. 从设备管理选择 IP，查看真实绑定上下文并跳回该设备流量；切顶部查看项目，流量独立筛选不改变。
4. 规则页输入非法 JSON 查看校验，修正后预览；查看 Header 的项目作用域和保存提示。
5. 在规则集页比较“优先顺序”和“运行步骤”，查看设备运行和重置提示。
6. 顶部切紧凑/舒适密度，确认日常阅读偏好。

## 6. 剩余行为的安排

本轮不再逐条要求确认工程内部命名。D18 的默认查询范围/目录层级、D16 草稿与空组操作在页面评审中结合画面处理；D04 同步候选等待与超时、D09 容量、D13 格式、D14 匹配和 D21 证书细则在对应实现前给出具体方案。

UI 稿获确认不代表这些未决行为已确认，也不代表核心或自动化验收通过。正式实现按已评审范围拆分，附上构建、核心验证和交互证据；真机测试时再提供可运行构建与操作步骤。

UI 评审决定 D22：运行控制属于设备，规则集页只编辑定义和查看关联设备，不直接开始/停止/重置。D23 已确认多关联、单个启用；界面布局通过不等于所有关联语义均已冻结。

关联模型 D23 已确认：设备 ↔ 规则集多对多；每设备同时至多启用一个。设备页区分已关联、本次候选、实际启用；启用/停止只影响本设备。规则集页展示关联设备的独立状态并跳转设备管理。
