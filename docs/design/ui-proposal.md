# MockCharles UI 方案草案

日期：2026-09-10。依据本轮四模块要求重新整理，替换旧七入口和布局备选；未开始应用实现。功能导航 + 工作区布局沿用既有确认，具体视觉与操作细节待评审。

## 1. 结构草图

```text
┌──────────────────────────────────────────────────────────────┐
│ 查看项目 ▾                  代理：未开启 [开启]  [设置]       │
├──────────────┬───────────────────────────────────────────────┤
│ 设备管理     │ 当前页面 / 范围 / 筛选 / 主要操作              │
│ 规则管理     ├────────────────────┬──────────────────────────┤
│ 规则集管理   │ 列表或目录         │ 详情 / 编辑 / 预览       │
│ 流量         │                    │                          │
└──────────────┴────────────────────┴──────────────────────────┘
```

证书在设备管理；接口规则与 Header 在规则管理；规则排序与原顺序 Mock 组在规则集管理；数据材料作为规则编辑辅助。项目和设置不占一级业务模块。

## 2. 页面内组织建议

| 页面 | 列表区 | 详情区 |
| --- | --- | --- |
| 设备管理 | IP、备注、最近活动、实际项目/规则集 | 接入与证书、配置绑定、运行、查看此 IP 流量 |
| 规则管理 | 接口规则 / Header 规则页签 | 匹配、固定/随机响应、Header 操作、样本/业务记录选择 |
| 规则集管理 | 优先匹配 / 顺序执行类型入口 | 引用规则、排序、影响设备；顺序运行按设备查看 |
| 流量 | 全部 IP / 指定 IP；流式列表 / 目录树 | 实际请求响应、命中与版本、创建规则 |

顶部查看项目只控制配置浏览。建议流量使用独立项目筛选并默认全部项目，包含未绑定来源，避免“全部流量”实际只显示一个项目。此默认值仍待 D18。

流量页控制顺序建议：范围（全部 IP/单 IP）→ 项目及其他筛选 → 展示（流式/目录式）。目录建议按协议+域名+端口/路径/请求实例组织。同一记录共用详情，切换展示保持选中记录和筛选。

## 3. 原型评审流程

1. 两台设备接入、下载公共证书并核对信任状态；新 IP 默认真实转发。
2. 全部 IP 流式找到请求 → 切目录式仍定位同一请求 → 从设备入口查看单 IP 的两种视图。
3. 从真实响应创建接口规则 → 编辑并预览 → 加入优先规则集 → 绑定设备 → 下一请求核对 Mock 与 Header。
4. 从样本/业务记录构建随机响应，核对保存版本和流量中的本次实际结果。
5. 同一顺序定义供两个 IP 使用，各自开始和推进；规则集定义与设备运行分开显示。
6. 切换查看项目不改变绑定；设备改绑不改变历史流量项目归属。

## 4. 必须展示的异常状态

代理未开启/监听失败、证书未信任或无法判断、新 IP 未绑定、规则未加入任何规则集、规则集没有有效项、无命中、运行完成、生成/写出失败、共享规则影响提示、版本冲突、正文未保存/截断、HTTPS 未解密、查询无结果。

原型数据需标注为演示；评审不代表真实代理和手机联调已完成。完整行为见 [桌面交互](08-desktop-ui.md)，遗漏与未决事项见 [项目规划](../project-plan.md) 和 [决策登记](decisions.md)。
