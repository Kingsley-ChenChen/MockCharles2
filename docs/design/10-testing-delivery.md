# 10 验证、实施顺序与交付

这是实现阶段的验证计划，当前未执行应用测试。性能高效、包体小是方向；达标数值及负载尚待 D12。

## 1. 关键技术验证先行

| 验证 | 最小实验 | 通过证据/失败影响 |
| --- | --- | --- |
| Wails 双平台 | Windows/macOS 各自构建最小界面并调用 Go | 原生运行、关闭退出；平台依赖不满足则调整构建环境 |
| 手机 HTTPS | Android/iOS 各一条自研 JSON 请求经代理 | 原文/修改/实际返回一致，记录证书配置与协商 |
| 代理候选库 | Header、多值、压缩、取消、并发 | 缺能力则在代理适配层替换，核心接口保持 |
| SQLite | 配置并发更新与捕获并行写入 | 版本冲突正确、配置事务完整、积压可控 |
| MCP | 每目标客户端连接本机并完成 CRUD | 记录客户端/SDK/协议版本，不以文档支持替代实测 |

环境搭建先确认目标系统和依赖版本，再安装。当前仅完成只读盘点，没有修改电脑代理、信任证书或安装软件。

## 2. 模块实现顺序

1. 工程骨架与本地数据：Wails、Vue、Go 核心接口、SQLite 迁移、统一错误。
2. 设备与真实代理闭环：同端口 IP 识别、HTTP/HTTPS、流量查询、关闭退出。
3. 固定独立 Mock：规则集、原始请求匹配、双向 Header、规则顺序、样本提取。
4. 业务记录与随机：编辑生成、预览、类型与资源校验、响应版本更新。
5. 顺序组：手动控制、完整写出后推进、多设备隔离、并发及重置竞争。
6. MCP：复用已稳定管理接口、服务端权限、各客户端联调。
7. 打包与容量验证：两平台安装、目标设备矩阵、性能/保留、文档与分发。

顺序不是工期承诺。D01/D02/D03 已确认；其他未决项在进入对应模块前收口。每阶段输出可演示的用户闭环，不先搭满所有页面再补真实代理。

## 3. 核心验收用例

| ID | 场景 | 必须结果 |
| --- | --- | --- |
| A01 | 两 IP 共用端口 | 独立设备选择、独立运行游标 |
| A02 | IP 改变 | 新设备真实转发，需手动选择 |
| A03 | 两设备复用规则集 | 相同规则顺序可复用，设备模式各自独立 |
| A04 | 两独立规则同时匹配 | 第一个启用规则命中并可解释 |
| A05 | 组当前步之外请求 | 真实服务，通用 Header 仍生效，不回退独立 Mock |
| A06 | 最后一步完成 | 后续真实转发，手动重置/开始才能再运行 |
| A07 | 生成或写出失败 | 明确错误/交付失败记录，游标不变 |
| A08 | 响应保存与请求并发 | 在途旧版本，下一请求新版本，日志准确 |
| A09 | 修改组顺序/步骤开关 | 本次顺序保持，下次开始/重置采用新配置 |
| A10 | 三个开关分别关闭 | 捕获、独立规则、组步骤互不错误联动 |
| A11 | 切出组或改绑 | 旧运行停止，新运行手动开始 |
| A12 | 重置时旧请求回调 | 不能推进新 runId/generation |
| A13 | 多值 Header 和压缩正文 | 实际输出符合修改、长度和编码一致 |
| A14 | 删除/修改源业务记录 | 已保存响应模板保持不变 |
| A15 | AI 与 UI 同版本修改 | 一个成功另一个版本冲突 |
| A16 | AI 尝试控制运行或夹带字段 | 工具层与核心层均无法执行 |
| A17 | 关闭窗口并重启 | 监听停止；重启不自动续跑 |
| A18 | 随机约束不可满足 | 有界失败，无无限循环、无上游回退 |

对 D04/D05/D06/D09/D10 等未决行为，测试先写期待清单，确认后才固定断言，避免测试替用户作决定。

## 4. 验证层次

匹配器/生成器以纯输入输出验证边界和不变量；组运行测试并发预占、写出失败和代次；存储集成测试事务与版本冲突；真实手机和两平台测试验证代理/证书/宿主无法由单元测试覆盖的部分。

随机测试固定测试种子以复现故障，重点检查范围、类型、唯一性及终止，不用“每次必须不同”作断言。性能测试隔离有/无持久捕获，比较真实转发、固定 Mock、随机 Mock，防止混淆磁盘与生成开销。

## 5. 性能测量表

D12 需补全设备数、并发数、请求速率、正文大小、随机列表长度、持续时间、磁盘及目标 OS/CPU。记录安装包/解压大小与额外运行时下载、冷/热启动、空闲/峰值内存、p50/p95/p99 延迟、错误率、队列峰值、磁盘增长、UI 更新延迟。

测试结果需带构建版本和录制策略；平均延迟不能替代尾延迟和错误率。未确认阈值前仅报告测量，不写“已达到高性能”。

## 6. 交付门槛

详细设计评审：剩余会改变行为的决策已确认并同步各文档。
功能验收：上述场景在确定的目标矩阵上通过，错误与限制可观察。
分发验收：安装/升级/退出、WebView 依赖、签名与平台提示符合 D11。
AI 验收：每个承诺客户端都有实际 CRUD 证据。

下一份产物是按这些阶段拆分的开发任务及验收清单；在开始写应用前，优先完成并发/生命周期等剩余选择。
