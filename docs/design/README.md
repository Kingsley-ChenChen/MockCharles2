## 当前阶段与交付形态

下一阶段是详细设计评审，随后做关键技术验证，再按模块实现。产品形态已确认：Windows/macOS 桌面客户端，Wails v2 宿主内包含 Vue 界面、Go 代理与管理核心、SQLite 本地数据。前后端在代码与职责上分离，共同打包交付；不要求用户另部署后端服务器。团队服务留到后期。

界面通过桌面绑定调用核心，手机连接局域网代理入口，AI 经 MCP 适配器调用管理核心。这三类入口职责不同，不共用手机代理端口提供管理功能。

## 不变的设计基线

1. 多台手机共用代理端口，以连接实际来源 IP 区分；新 IP 真实转发，手动配置。
2. 每个 IP 独立选择真实转发、独立 Mock、顺序 Mock 组三种模式。
3. 独立模式取适用列表中第一条启用且匹配的规则；组模式只匹配当前步骤，不回退到独立 Mock。
4. 组未命中或已完成时真实转发；所有可解密处理的 HTTP 路径都应用通用 Header，命中接口的 Header 再覆盖。
5. 组最后一步完成即结束；切出组模式或改绑其他组停止旧运行；重启和新组均手动开始。
6. 数据源仅在编辑阶段参与响应生成；固定响应与每请求随机生成均在首版。
7. 响应/随机配置保存后下一请求生效；在途请求保留选定版本；组顺序及步骤开关下次开始/重置生效。
8. 抓包保存、独立规则启用、组步骤启用相互独立。
9. AI 可以管理 Mock 数据与规则，首版不能切换模式、绑定设备或开始/停止/重置运行。
10. 关闭窗口退出并停止代理。没有独立常驻代理服务。

## 设计状态的解释

“已确认”来自用户答复；“实现建议”是可评审的内部技术设计；“待确认 Dxx”是仍需用户选择的产品行为。实现建议若改变用户可见行为，必须先纳入决策清单。

本系列已细化稳定部分的模块、数据和流程。D01—D03 已确认：设备可复用规则集、按单记录模板生成列表、完整写出成功后推进；其他问题集中保留，不在不同文档中各自猜测。未决项不妨碍阅读与估算，但相关实现和验收不得按建议默认冻结。
